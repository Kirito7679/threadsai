# 🧵 Threads Autopilot

Платформа автоматизации Threads: подключается к вашему аккаунту, изучает популярные ветки
в нише, генерирует посты через DeepSeek, публикует по расписанию после вашего одобрения
и собирает аналитику.

Работает **только через официальный Threads API** от Meta — никакого парсинга и логинов
через браузер, риска блокировки аккаунта нет.

---

## Что умеет

| Блок | Что происходит |
|---|---|
| **Разведка** | Каждые 6 часов ищет посты по вашим ключевым словам через `keyword_search` в двух режимах: `TOP` (популярное) и `RECENT` (свежее). DeepSeek разбирает каждый пост: тема, тип зацепки, формат, тон, почему цепляет. |
| **Тренды** | Из разобранных постов строится отчёт: что происходит в нише, какие тренды работают, конкретные идеи для постов, что уже заезжено. |
| **Генерация** | Ежедневно в 8:00 ИИ пишет ветки, опираясь на тренды, ваш тон голоса, ваши лучшие посты и статистику по рубрикам. |
| **Модерация** | Черновики ждут в очереди: одобрить, отредактировать, переписать с замечанием, опубликовать сразу или отклонить. |
| **Публикация** | Каждые 2 минуты проверяет расписание. Ветки публикуются цепочкой: первый пост, остальные — ответами к нему. |
| **Аналитика** | Раз в час — метрики каждого поста (просмотры, лайки, ответы, репосты, цитаты, шеры) во временной ряд. Раз в сутки — метрики аккаунта и подписчики. |
| **Выводы** | Дашборд показывает, какие рубрики и часы публикации реально дают охват. Эти выводы уходят обратно в промпт генератора. |

## Ограничение, о котором нужно знать

Официальный API **не отдаёт лайки и просмотры чужих постов**. Прокси популярности —
параметр `search_type=TOP`: Threads сам ранжирует выдачу по популярности, и мы используем
попадание в топ как сигнал. Точные цифры конкурентов можно получить только парсингом,
что нарушает правила Meta — здесь этого нет сознательно.

## Шаг 1. Приложение Threads

1. Откройте [developers.facebook.com/apps](https://developers.facebook.com/apps) → **Create App**.
2. Выберите сценарий использования **Threads API**.
3. Включите разрешения: `threads_basic`, `threads_content_publish`, `threads_manage_insights`,
   `threads_read_replies`, `threads_manage_replies`, `threads_keyword_search`.
4. В **Redirect Callback URL** укажите:
   `https://ваш-домен.up.railway.app/auth/callback`
5. Скопируйте **Threads App ID** и **Threads App Secret**.

Аккаунт Threads должен быть **публичным** и переведён в **профессиональный режим**
(Настройки → Аккаунт → Профессиональный аккаунт), иначе Meta не выдаст разрешения.

## Шаг 2. Ключ DeepSeek

Получите ключ на [platform.deepseek.com](https://platform.deepseek.com) → API keys.

## Шаг 3. Деплой на Railway

```bash
git init
git add .
git commit -m "Threads Autopilot"
```

Дальше в Railway: **New Project → Deploy from GitHub repo** (или `railway up` через CLI).

Добавьте плагин **Postgres** (New → Database → PostgreSQL). Без него данные будут
в SQLite и пропадут при передеплое.

Переменные окружения (Variables):

```
THREADS_APP_ID=...
THREADS_APP_SECRET=...
THREADS_REDIRECT_URI=https://ваш-домен.up.railway.app/auth/callback
APP_BASE_URL=https://ваш-домен.up.railway.app
DASHBOARD_PASSWORD=придумайте-пароль
SECRET_KEY=длинная-случайная-строка
DATABASE_URL=${{Postgres.DATABASE_URL}}
DEEPSEEK_API_KEY=...
TIMEZONE=Europe/Moscow
```

> `SECRET_KEY` шифрует токены Threads в базе. Если поменять его позже — токен
> перестанет расшифровываться и аккаунт придётся подключить заново.

В настройках сервиса включите **Generate Domain**, чтобы получить публичный адрес,
и убедитесь, что реплика одна (планировщик не должен работать в нескольких копиях).

## Шаг 4. Первый запуск

1. Откройте домен → введите `DASHBOARD_PASSWORD`.
2. Нажмите **Подключить Threads** → подтвердите доступ.
3. **Настройки** → заполните нишу, аудиторию и тон голоса. Тон голоса — самое важное поле,
   модель следует ему дословно.
4. **Тренды** → добавьте 10–15 ключевых слов ниши → **Запустить разведку**.
5. **Очередь** → **Сгенерировать** → проверьте черновики → **Запланировать**.

Дальше система работает сама. Вам остаётся заходить в очередь и одобрять.

## Локальный запуск

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
copy .env.example .env
.venv\Scripts\uvicorn app.main:app --reload
```

Для локального OAuth в приложении Threads добавьте второй Redirect URL
`http://localhost:8000/auth/callback` и укажите его в `.env`.

Проверка без сети (все внешние вызовы подменяются заглушками):

```bash
.venv\Scripts\python smoke_test.py
```

## Структура

```
app/
  main.py          FastAPI, middleware авторизации, старт планировщика
  config.py        переменные окружения
  db.py            движок SQLAlchemy (Postgres или SQLite)
  models.py        таблицы: аккаунты, ключевые слова, разведка, тренды,
                   черновики, посты, метрики, журнал задач
  security.py      шифрование токенов (Fernet) и подписанные cookie
  threads_api.py   клиент Threads API: OAuth, публикация, insights, поиск
  llm.py           клиент DeepSeek
  accounts.py      токены, настройки аккаунта
  research.py      сбор популярных веток и отчёт по трендам
  generator.py     генерация черновиков и слоты расписания
  publisher.py     публикация цепочек, контроль суточной квоты
  analytics.py     сбор метрик и агрегации
  scheduler.py     фоновые задачи APScheduler
  routes/          auth.py (вход, OAuth), ui.py (панель)
  templates/       страницы Jinja2
  static/style.css оформление
smoke_test.py      автономная проверка всей логики
```

## Лимиты платформы

| Лимит | Значение |
|---|---|
| Публикаций в сутки | 250 |
| Символов в одном посте | 500 (генератор режет по 480) |
| Поисковых запросов в сутки | 2200 |
| Срок жизни токена | 60 дней, продлевается автоматически раз в сутки |

## Автопилот

В настройках есть переключатель **Автопилот** — черновики публикуются без модерации.
Включайте, когда качество генерации стабильно устраивает: система уже будет знать,
какие рубрики дают охват на вашем аккаунте.

# Подключение Threads API — подробная инструкция

## Почему Facebook

Threads принадлежит Meta — той же компании, что Facebook и Instagram. Все приложения
Meta создаются в одном кабинете разработчика, который живёт на домене `facebook.com`.

Это значит:

- **Нужен аккаунт Facebook** — только чтобы войти в кабинет разработчика.
- **Связывать его с вашим Threads не нужно.** Threads подключится отдельно, через
  обычную кнопку «Подключить» в панели, где вы войдёте своим логином Threads.
- Аккаунт Facebook может быть каким угодно, хоть пустым и новым.

Если аккаунта Facebook нет — зарегистрируйте на [facebook.com](https://facebook.com).
Всё, что от него нужно, — вход в кабинет.

---

## Шаг 1. Кабинет разработчика

1. Откройте [developers.facebook.com](https://developers.facebook.com) и войдите
   под аккаунтом Facebook.
2. Нажмите **Get Started** (в правом верхнем углу, если вы там впервые).
3. Meta попросит подтвердить телефон или почту и выбрать род занятий — выбирайте
   любой подходящий вариант, на возможности это не влияет.

## Шаг 2. Создание приложения

**Прямая ссылка на форму создания:**
https://developers.facebook.com/apps/create/

Список всех ваших приложений: https://developers.facebook.com/apps/

> **Не видно кнопки «Create App» / «Создать приложение»?**
> - Вы не вошли в аккаунт — ссылка перекинет на страницу входа Meta.
> - Не пройдена регистрация разработчика (шаг 1): пока она не завершена,
>   список приложений пуст и кнопки нет.
> - Интерфейс на русском: ищите **«Создать приложение»** в разделе
>   **«Мои приложения»**.

1. Откройте ссылку выше — она ведёт сразу на первый шаг мастера.
2. **App name** — любое, например `Threads Autopilot`. Пользователи его не увидят,
   пока приложение не опубликовано.
3. Contact email — ваша почта.
4. На шаге выбора сценария (**Use cases** / «Что должно делать ваше приложение?»)
   выберите **Access the Threads API**.

   > Это ключевой момент. Если выбрать другой сценарий, разрешений Threads в
   > приложении не появится, и придётся создавать новое.

5. Завершите создание — откроется панель приложения.

## Шаг 3. Разрешения

В левом меню: **Use cases** → у строки **Access the Threads API** нажмите **Customize**.

Включите (кнопка **Add** напротив каждого):

| Разрешение | Зачем |
|---|---|
| `threads_basic` | Обязательное, без него не работает ничего |
| `threads_content_publish` | Публикация постов |
| `threads_manage_insights` | Аналитика: просмотры, лайки, подписчики |
| `threads_read_replies` | Чтение ответов |
| `threads_manage_replies` | Ответы и скрытие комментариев |
| `threads_keyword_search` | Поиск популярных веток — на нём держится вся разведка |

## Шаг 4. Redirect Callback URL

В том же разделе сценария откройте вкладку **Settings**.

В поле **Redirect Callback URLs** вставьте адрес вашего приложения с `/auth/callback`
на конце:

```
https://ваш-домен.up.railway.app/auth/callback
```

Требования:

- Строго **https** (localhost — исключение, для него допустим http).
- Адрес должен совпадать с переменной `THREADS_REDIRECT_URI` **до последнего символа**.
  Лишний слэш на конце — и авторизация упадёт с ошибкой `redirect_uri mismatch`.
- Можно добавить несколько адресов: боевой и `http://localhost:8000/auth/callback`
  для локальной разработки.

Если форма требует **Uninstall callback URL** и **Delete callback URL** — впишите
корень вашего домена, эти вебхуки платформа не использует.

Нажмите **Save**.

## Шаг 5. Threads App ID и Secret

⚠️ **Самая частая ошибка.** У приложения два набора ключей: обычный **App ID** от
Meta и отдельный **Threads App ID**. Нужен именно второй, иначе OAuth будет
возвращать ошибку.

Ищите на той же странице сценария **Access the Threads API**, вкладка **Settings** —
блок с подписями **Threads App ID** и **Threads App Secret**. Секрет откроется по
кнопке **Show** после ввода пароля Facebook.

Скопируйте оба значения.

## Шаг 6. Добавьте себя как тестировщика

Пока приложение не прошло проверку Meta, выдавать разрешения могут только
тестировщики. Для своего аккаунта проверка не нужна — достаточно этого шага.

1. В левом меню: **App roles** → **Roles** → **Add People**.
2. Выберите роль **Threads Tester**.
3. Введите ваш username в Threads (без `@`) и отправьте приглашение.
4. Откройте приложение Threads на телефоне:
   **Настройки** → **Аккаунт** → **Разрешения для сайтов** → **Приглашения** →
   примите приглашение.

   > Формулировки пунктов у Meta периодически меняются. Ищите раздел про
   > разрешения сторонних сайтов или приложений.

Без принятого приглашения авторизация завершится ошибкой доступа.

## Шаг 7. Ключи в Railway

В проекте Railway → вкладка **Variables** добавьте:

```
THREADS_APP_ID=<Threads App ID из шага 5>
THREADS_APP_SECRET=<Threads App Secret из шага 5>
THREADS_REDIRECT_URI=https://ваш-домен.up.railway.app/auth/callback
APP_BASE_URL=https://ваш-домен.up.railway.app
```

Сервис перезапустится сам. Откройте домен → **Подключить Threads** → подтвердите
доступ. Готово.

---

## Если что-то пошло не так

| Ошибка | Причина |
|---|---|
| `Invalid redirect_uri` | Адрес в кабинете Meta и в `THREADS_REDIRECT_URI` не совпадают символ в символ |
| `Invalid client_id` | Взят обычный App ID вместо **Threads App ID** (шаг 5) |
| При входе не показывается запрос разрешений | Аккаунт не добавлен как Threads Tester или приглашение не принято (шаг 6) |
| `Insufficient permissions` при поиске | Не включено `threads_keyword_search` (шаг 3) |
| Проверка state не пройдена | Прошло больше 15 минут между нажатием кнопки и подтверждением — начните заново |

## Нужна ли проверка приложения (App Review)

**Для вашего собственного аккаунта — нет.** Приложение остаётся в режиме разработки,
вы работаете как Threads Tester, все функции доступны.

Проверка Meta понадобится, только если платформой будут пользоваться посторонние люди
со своими аккаунтами. Тогда каждое разрешение проходит ревью и приложение публикуется.

## Про аккаунт Threads

Жёстких требований к типу аккаунта у API нет, но публичный профиль работает лучше:
закрытые аккаунты не попадают в поиск, а часть статистики по ним недоступна.
